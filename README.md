# Параллельная жизнь (Parallel Life)

Небольшой симулятор жизни современного города в пиксельном стиле. 21 персонаж — 20 жителей
и **Даня** (`player_avatar`), виртуальная версия пользователя, — сами работают, учатся, знакомятся,
ссорятся, ищут работу, получают повышения, запускают проекты и ошибаются. Вы наблюдаете за
ними, особенно за Даней: его идеи складываются в отдельный архив, откуда их можно забрать
в реальную жизнь.

> Идеи в архиве — продукт симуляции. Приложение **не проверяет** спрос, доходность и
> конкурентов: у каждой идеи стоит статус «не проверена», а в рисках прямо написано, на чём
> она основана.

## Быстрый старт

Нужен **Node.js 22.13+** (используется встроенный модуль `node:sqlite`, нативные зависимости
не нужны).

```bash
npm install
npm run dev        # сервер + интерфейс с горячей перезагрузкой → http://127.0.0.1:5173
```

**Каждый запуск сервера начинает мир с нуля**: понедельник, 07:00, время на паузе, у всех жителей
стартовое состояние (новый случайный seed). Архив идей при этом сохраняется. Если нужно
продолжить прошлый мир — `npm run dev:continue` / `npm run start:continue` (или `PL_CONTINUE=1`).
Обновление страницы в браузере мир не сбрасывает.

Все суммы показываются в рублях (₽).

Другие команды:

| Команда | Что делает |
| --- | --- |
| `npm start` | собирает интерфейс и запускает production-сервер (раздаёт `dist/`) |
| `npm run serve` | запускает сервер без пересборки |
| `npm run dev:continue`, `npm run start:continue` | то же, но продолжить мир с прошлого запуска |
| `npm test` | автотесты (vitest) |
| `npm run typecheck` | проверка типов TypeScript |
| `npm run simulate -- 90 42` | консольный прогон: 90 игровых дней, seed 42 — без интерфейса |

Переменные окружения (см. `.env.example`): `PORT` (по умолчанию 5173), `HOST`
(по умолчанию 127.0.0.1 — для доступа с планшета в локальной сети укажите `0.0.0.0`),
`PL_DB_PATH` (по умолчанию `data/parallel-life.db`).

При запуске Node выводит предупреждение `ExperimentalWarning: SQLite is an experimental feature` —
это нормально для `node:sqlite` в Node 22.

## Открыть по ссылке (GitHub Pages)

В репозитории есть автопубликация `.github/workflows/pages.yml`. После включения игра доступна по
адресу `https://<пользователь>.github.io/<репозиторий>/` (для этого репозитория —
https://tsum323.github.io/gorodok/).

1. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. Код должен попасть в ветку `main` (публикация запускается при каждом её обновлении; вручную —
   Actions → GitHub Pages → Run workflow).

На Pages нет сервера, поэтому мир хранится в браузере (localStorage): при обновлении страницы он
продолжается, начать заново можно в настройках. Экспорт файлов работает.

## Что реализовано

**Мир и персонажи.** 21 персонаж с разными характерами (10 черт), навыками (9), деньгами, долгами,
жильём, потребностями (энергия, сытость, общение, отдых), настроением, стрессом, удовлетворённостью
жизнью, целями (долгосрочными и текущими), краткосрочными планами, памятью, историей и журналом
решений. Среди них — основатель IT-компании, осторожная руководительница, импульсивный разработчик,
ценящая свободное время программистка, стажёр, владельцы кафе, магазина и коворкинга,
предпринимательница, фрилансеры, студенты, профессор, человек в поиске работы, люди, меняющие
профессию. 7 организаций, 9 локаций.

**Иерархия.** Стажёр → специалист → старший → руководитель, а также предприниматель, владелец
бизнеса и влиятельный участник. Деньги, должность, репутация и влияние — разные параметры.

**Время.** Пауза, шаг (+1 час), ×1, ×4, ×15 и «Макс» (сколько успевает за кадр при ограниченном
бюджете времени — интерфейс остаётся отзывчивым). Один шаг = один игровой час. Учитываются
рабочие часы, сон, дорога между локациями (1 час), выходные, ежедневные и еженедельные расчёты.

**Решения.** Каждый персонаж выбирает действие, когда закончилось предыдущее (а не каждый час),
по модели полезности: потребности + цели + характер + ресурсы + место + немного шума
(импульсивные менее предсказуемы). Важные решения (уволиться, начать проект, откликнуться
на вакансию, присоединиться к проекту) записываются с причиной, рассмотренными альтернативами
и ожиданием; позже к ним дописывается фактический итог. У Дани журнал подробнее: каждое
небытовое действие с альтернативами и оценками.

**Взаимодействия.** Знакомства, болтовня (с учётом совместимости характеров), рассказ о проблемах
(обмен информацией), советы и наставничество, наводки на вакансии (повышают шанс найма),
предложения о сотрудничестве (договорённость + участник проекта + задача), ссоры
(соперничество за вакансию, нарушенные договорённости, раздражение), нарушение договорённостей
участником, который пропал из проекта. Отношения направленные: «А считает Б другом» не означает
обратного.

**Экономика.** Зарплаты из кассы организаций, выручка организаций от «внешнего рынка», аренда и
расходы на жизнь, покупки в магазине и кафе (деньги переходят владельцу), фриланс-заказы, долги с
процентами, премии, выплаты владельцам, проекты с затратами, пользователями и выручкой.
Деньги не появляются из ничего: изменение суммы денег в мире всегда равно разнице внешних
поступлений и расходов (проверяется тестом и `npm run simulate`).

**Карьера.** Вакансии, отклики, конкурс кандидатов, отказы, рекомендации, еженедельные ревью
(повышение требует эффективности, стажа на ступени, навыка и денег у компании; есть лимит
руководителей), предупреждения и увольнения, сокращения в бедных компаниях, увольнение по
собственному решению.

**События.** Единая система: у каждого события есть ID, порядковый номер, время, тип, участники,
место, причина, контекст, изменения, важность, ссылки и (для разговоров) короткий диалог.
Случайные события (болезнь от переутомления, премия, непредвиденные расходы, вирусный пост
о проекте, новости технологий и др.) срабатывают только при выполнении условий.

**Главный персонаж и идеи.** Даня — обычный житель без сюжетной неуязвимости: может влезть в долги,
получить предупреждение, провалить проект. Он замечает проблемы на работе и в городе, слышит о
них в разговорах, изучает технологии и, когда размышляет, превращает наблюдения в идеи.
Идея собирается из конкретного наблюдения, известных миру технологий (часть открывается
«новостями»), его навыков, целей, знакомых (возможный партнёр) и прошлых неудач. Защита от
дубликатов — по сочетанию «проблема × технология» и названию; есть пауза между идеями и лимит в
неделю. Даня сам решает, запускать ли проект по лучшей идее.

**Ключевые моменты.** Переломные события выделяются отдельно: начало, запуск, успех
(50 и 200 пользователей, первый вирусный рост), провал или заброс проекта, уход в долги и выход
из них, найм, смена работы, увольнение, повышение, сильная идея Дани (8/10 и выше). Они отмечены
цветной плашкой в ленте (▲ взлёт, ▼ падение, ◆ поворот), собраны фильтром «★ Ключевые», всплывают
баннером над сценой и хранятся в профиле каждого персонажа в блоке «Переломные моменты».

**Архив идей.** Новая идея при открытии карточки сама становится «Просмотрена», дальше статус
меняете вы. Идеи можно выбирать по одной или «Выбрать все» и разом добавлять в избранное (или
убирать), экспортировать и удалять (с подтверждением; удалённая идея не придумывается заново).
Поиск по названию и содержанию, фильтры по статусу, дате и избранному, сортировка,
полная карточка (все поля из ТЗ), статусы (Новая, Просмотрена, Интересная, На проверке, В реализации, Отложена,
Отклонена), оценка звёздами, заметки, избранное, экспорт выбранных (или всех найденных) идей в
Markdown и JSON, копирование описания в буфер. Идеи никогда не удаляются автоматически и
переживают создание нового мира.

**Интерфейс.** Пиксельные SVG-спрайты (без внешних картинок), 7 сцен (жилой квартал, бизнес-центр,
коворкинг, кафе, улица, университет, магазин) с днём и ночью, позами (сидит, стоит, идёт, спит) и
индикаторами действий; камера может следовать за Даней. Лента событий с фильтрами и карточкой
события, список жителей с поиском и фильтрами, профиль персонажа (обзор, отношения, история,
решения, проекты, память), отдельный режим для Дани (подробный журнал решений, идеи,
наблюдения), настройки (имя, стартовые параметры, seed, экспорт/импорт, статус ИИ). Раскладка:
три колонки на компьютере, две + вкладки на планшете, вкладки на телефоне.

**Сохранение.** SQLite через локальный сервер: снимок мира, полная история событий, архив идей.
Автосохранение по игровому и реальному времени, при паузе и при закрытии вкладки. Экспорт и импорт
сохранения целиком. Если интерфейс открыт без сервера, используется localStorage (с ограничением
истории событий).

## Архитектура

```
src/sim/            Движок симуляции — чистый TypeScript, без React и браузера
  types.ts          Типы состояния мира (всё сериализуемо в JSON)
  seed.ts           Стартовый мир: персонажи, организации, знакомства, настройки Дани
  rng.ts            Детерминированный ГСЧ (mulberry32), состояние хранится в мире
  time.ts           Календарь и форматирование игрового времени
  engine.ts         Движок времени: tick() = 1 час, порядок фаз внутри шага
  planner.ts        Выбор действий (utility AI), ежедневный пересмотр целей и планов
  actions.ts        Каталог действий: доступность, полезность, эффекты
  needs.ts          Потребности, настроение, стресс, удовлетворённость
  social.ts         Отношения, совместимость, разговоры и диалоги
  economy.ts        Деньги: переводы, внешний рынок, ежедневный расчёт
  career.ts         Вакансии, найм, ревью, повышения, увольнения
  projects.ts       Проекты, сотрудничество, запуск, провалы
  decisions.ts      Журнал решений с объяснениями
  events.ts         Единая система событий, история и память персонажей
  randomEvents.ts   Случайные события с условиями
  ideas/            Наблюдения, каталоги проблем и технологий, генератор идей
  migrate.ts        Версия снимка мира и миграции
src/archive/        Поиск, фильтры и экспорт идей (чистые функции)
src/storage/        Адаптеры хранилища: SQLite-сервер или localStorage
src/app/            GameController: цикл времени, сохранение, связь с интерфейсом
src/ui/             React-компоненты (только отображение и вызовы контроллера)
server/             Node-сервер: REST API + SQLite (node:sqlite) + Vite в режиме dev
tests/              Тесты vitest
scripts/simulate.ts Консольный прогон мира
```

### Шаг симуляции

1. `world.time += 1`.
2. В полночь — ровно один раз в сутки: зарплаты и выручка, расходы и долги, итоги рабочего дня,
   проекты (пользователи, выручка, провалы, нарушенные договорённости), ослабевание старых
   знакомств, случайные события. В пятницу в 17:00 — ревью в организациях.
3. Каждый персонаж проживает час текущего действия: прибытие на место, изменение потребностей,
   эффект действия (работа, учёба, проект…).
4. Разговоры: открытые к общению персонажи заговаривают с теми, кто рядом.
5. Решения по откликам на вакансии, у которых подошёл срок.
6. Персонажи, у которых действие закончилось (или срочно нужны сон/еда), раз в день пересматривают
   цели (в свой час), затем выбирают следующее действие.

Обычные процессы считаются правилами; языковая модель на шаге не используется.
Одинаковый seed и одинаковые стартовые параметры дают одинаковый мир (проверено тестом).

### Хранение данных

* `data/parallel-life.db` (SQLite, путь меняется `PL_DB_PATH`):
  * `world` — снимок текущего мира (JSON) с seed и состоянием ГСЧ;
  * `events` + `event_participants` — полная история событий (только добавление, `INSERT OR IGNORE`
    по ID — повторное сохранение не создаёт дубликатов);
  * `ideas` — архив идей всех миров (не очищается при создании нового мира);
  * `meta` — служебные значения.
* Схема базы развивается миграциями (`PRAGMA user_version`, `server/db.ts`), формат снимка
  мира — функциями `MIGRATIONS` в `src/sim/migrate.ts`.
* В мире хранятся последние 400 событий (для ленты) и ограниченная история персонажей; полная
  история доступна в профиле по кнопке «Полная история из хранилища».
* Без сервера (например, если открыть только собранный `dist/`) данные лежат в localStorage этого
  браузера, полная история ограничена 3000 событиями.

### Как добавлять механики

* **Новое действие** — объект в массиве `ACTIONS` (`src/sim/actions.ts`): `plan()` (доступно ли,
  где, сколько длится), `score()` (полезность), `onStart/onHour/onEnd` (эффекты). Движок менять
  не нужно.
* **Новый тип события** — значение в `EventType` (`types.ts`) и запись в `EVENT_TYPES`
  (`events.ts`): подпись, иконка, тон. Создаётся через `emit()`.
* **Случайное событие** — объект в `RANDOM_EVENTS` (`randomEvents.ts`) с условием и вероятностью.
* **Проблемы и технологии для идей** — `PROBLEMS` и `TECHNOLOGIES` в `src/sim/ideas/catalog.ts`.
  Проблема описывает контексты, где её можно заметить (`org:cafe`, `state:debt`, `goal:…`).
* **Новое поле в состоянии** — добавить в типы, в `seed.ts` и шаг миграции в `migrate.ts`
  (увеличив `CURRENT_WORLD_VERSION`).

## ИИ: что есть и как подключить модель

Сейчас **языковая модель не используется**. Идеи, диалоги, объяснения решений и события строятся
правилами и шаблонами из состояния мира. Интерфейс честно показывает это в настройках
(`/api/health` → `ai.active: false`).

Точка расширения — интерфейс `IdeaGenerator` (`src/sim/ideas/generator.ts`):

```ts
interface IdeaGenerator {
  readonly name: 'rules' | 'llm';
  generate(ctx: { world; author; trigger }): IdeaDraft | null;
}
```

Чтобы подключить модель:

1. Добавить на сервер эндпоинт (например, `POST /api/ai/idea`), который получает контекст
   (наблюдение, навыки, цели, знакомых) и вызывает API модели. Ключ брать из переменной окружения
   `LLM_API_KEY` (в `.env`, файл в `.gitignore`), не из кода. Статус — в `server/ai.ts`.
2. Так как движок синхронный и детерминированный, вызывать модель асинхронно поверх уже созданной
   правилами идеи (например, «улучшить формулировку» по кнопке в архиве или в фоне), записывая
   результат с `generator: 'llm'`. Тогда воспроизводимость симуляции не нарушится, а ошибки модели
   не остановят мир (это уже обеспечено изоляцией ошибок в `tryGenerateIdea`).
3. По тому же принципу можно расширить диалоги (`social.ts`) и объяснения решений (`decisions.ts`).

Режим исследования идеи по внешним источникам не реализован и не имитируется.

## Тесты

`npm test` — 60 тестов: время и ограничение шагов, воспроизводимость, сохранение денег, отсутствие
отрицательных балансов, долги, одноразовый ежедневный расчёт, отношения (без повторных знакомств,
асимметрия, ссоры), уникальность и полнота событий, принятие решений (еда, сон, работа, характер,
цели), журнал решений Дани, идеи (контекст, отсутствие дубликатов, пауза, изоляция ошибок
генератора), архив (поиск, фильтры, сортировка, экспорт), SQLite (миграции, перезапуск, отсутствие
дубликатов событий, сохранность архива при сбросе мира, экспорт/импорт) и контроллер (продолжение
мира после «перезапуска»).

## Ограничения

* Экономика упрощённая и условная (суммы в рублях, но масштаб цен и зарплат условный), не модель реального города.
* Тексты на шаблонах, глаголы в форме «сделал(а)».
* Идеи генерируются правилами из конечного каталога проблем и технологий — со временем они
  начинают повторять темы (но не сочетания).
* Сохраняется один текущий мир (по умолчанию он начинается заново при каждом запуске сервера); архив идей общий для всех миров.
* Сервер рассчитан на локальное использование одним человеком (без авторизации).
